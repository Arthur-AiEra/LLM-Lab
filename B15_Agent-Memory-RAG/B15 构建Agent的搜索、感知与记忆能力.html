2. Agent 记忆演进：从金鱼到大脑

2.1 原生 Agent (短期工作记忆)

  • 机制： 将对话或上传的文件直接放在内存列表 (List) 中。
  • 痛点：
    • 临时性： 生命周期仅限单次请求，典型的“金鱼记忆”。
    • 低效性： 每次需重新解析，无法处理海量文档（如上亿数据）。

2.2 进阶 Agent (长期语义记忆)

  • 引入持久化： 使用文件系统缓存 (doc_parser) 或 数据库。
  • 解决方案： 引入 Elasticsearch (ES)。
  • 优势： 毫秒级检索海量数据，支持 BM25 (关键词) 和 Vector (语义) 的混合检索。

3. 开发迭代路径 (V1 - V5)

版本 核心功能 技术实现点
Version 1 多文件快速检索 实现基础的文件上传与解析，针对少量文件进行内存级检索。
Version 2 海量文件索引 (ES) 引入 Elasticsearch，将解析后的数据存入 ES，实现关键词检索。
Version 3 向量检索功能 在 ES 中增加向量字段，实现 Hybrid Search (关键词+向量)，提升召回准确率。
Version 4 外部数据源 (MCP) 集成 AI 搜索 MCP (Model Context Protocol)，连接外部实时信息。
Version 5 界面美化 使用 Gradio 优化 UI，增加侧边栏、知识库管理、历史记录，实现 Stream 流式输出。

4. 核心技术：Elasticsearch (ES)

在 Agent 构建中，ES 不仅仅是搜索引擎，更是 Agent 的长期记忆体。

  • 混合检索 (Hybrid Search)： 结合了 Keyword Search (精确匹配) 和 Vector Search (语义模糊匹配)。
  • 元数据管理： 可以将页码 (Page)、来源 (Source) 等作为 Metadata 存储，检索时一同返回，方便定位原文。
  • 全能选手： 相比于纯向量数据库，ES 同时具备强大的全文检索能力。

5. 课堂精华 Q&A (实战避坑)

Q: ES 比较臃肿，是不是 Milvus 更好？ 陈博士： ES 是个全能选手，它同时支持 1) 关键词检索 2) 向量检索。Milvus 是专用的向量数据库。在需要混合检索和复杂元数据过滤的场景下，ES 依然非常强大。
Q: 如何让 Agent 的回答更快一些？ 优化策略：
  1. 利用 ES 现成的索引，避免重复解析。
  2. 控制上下文长度： RAG 返回给 LLM 的 Context 不要太长，Input Token 越长，Response 时间越长。
Q: 比赛中的特征工程问题（MAE结果偏高）？ 建议：
  • 先询问 Cursor/LLM 针对该场景（如二手车预测）有哪些高价值特征。
  • 特征数量 120 个左右效果较好。
  • 尝试模型融合、5折交叉验证。
  • 清洗掉异常数据（如价格为负数）。
Q: ES 检索结果能包含页码吗？ 实现： 可以将 Page (页码) 作为元数据 (Metadata) 存入 ES，检索时直接读取该字段即可。
Q: Qwen-Agent 适合做复杂流程编排吗？ 对比： Qwen-Agent 更适合自主决定使用什么工具（Function Calling）；如果需要编排固定的长链路工作流，LangGraph 会更适合。
