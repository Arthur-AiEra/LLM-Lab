Qwen-Agent RAG 实现机制分析

概述

Qwen-Agent 的 RAG（检索增强生成）功能通过文档解析、分块、存储和检索四个核心环节实现，能够在处理用户查询时动态从相关文档中提取信息，增强模型的回答质量。

RAG 实现组件

graph TD A[用户查询] --> B[retrieval.py - RAG入口] B --> C[doc_parser.py - 文档解析] C --> D[文档分块处理] D --> E[storage.py - 存储缓存] E --> F[search_tools - 检索引擎] F --> G[文档匹配与排序] G --> H[检索结果返回] H --> I[LLM 生成答案] J[文档输入] --> C C --> K[分块存储到workspace/tools] K --> F

核心代码位置

  • 主入口: qwen_agent/tools/retrieval.py - RAG 主工具类，协调文档解析和检索
  • 文档解析: qwen_agent/tools/doc_parser.py - 文档加载、分块与预处理
  • 存储机制: qwen_agent/tools/storage.py - 基于文件系统的键值存储
  • 检索引擎: qwen_agent/tools/search_tools/base_search.py - 检索算法基类
  • 混合搜索: qwen_agent/tools/search_tools/hybrid_search.py - 多种检索方法组合

文档分块策略

  1. Token 数量控制: 如果文档总 Token 数小于设定阈值(max_ref_token)，则整个文档作为一个块处理
  2. 分页处理: 基于文档页码进行内容组织
  3. 固定大小分块: 当文档较大时，按 parser_page_size 进行分块
  4. 句子级分割: 对于过长段落，按句子边界进行分割
  5. 重叠处理: 块之间保留部分内容重叠，确保上下文连续性

存储机制采用基于文件系统的键值存储，存储路径为 workspace/tools/doc_parser/，使用文档 URL 和参数生成的哈希值作为键，实现了文档处理结果的持久化缓存。

检索机制

graph TD A[用户查询] --> B[Query 预处理] B --> C[多搜索引擎并行检索] C --> D[BM25 传统检索] C --> E[语义相似度检索] D --> F[结果排序与评分] E --> F F --> G[HybridSearch 混合得分] G --> H[Top-K 选择] H --> I[Token 限制裁剪] I --> J[返回检索结果] K[文档块] --> D K --> E

检索算法

  1. BaseSearch: 抽象基类，定义了检索接口和基础处理流程
  2. HybridSearch: 混合搜索，结合多种检索方法的结果
  3. 评分机制: 根据位置加权（1/(rank+1+60)）整合不同搜索结果
  4. Token 控制: 按照 max_ref_token 参数限制返回的上下文长度

RAG 工作流程

sequenceDiagram participant U as 用户 participant A as Assistant Agent participant R as Retrieval Tool participant DP as DocParser participant S as Storage participant SE as Search Engine U->>A: 发送查询 "介绍下雇主责任险" A->>R: 调用 retrieval 工具 R->>DP: 解析文档 DP->>S: 检查缓存 S-->>DP: 缓存未命中/返回缓存 DP->>DP: 文档分割成块 DP->>S: 存储分块结果 R->>SE: 搜索相关块 SE->>SE: 计算相似度 SE->>R: 返回 Top-K 结果 R->>A: 返回检索内容 A->>U: 生成最终回答

详细步骤

  1. 初始化: Assistant Agent 接收用户查询和文件列表
  2. 文档解析: 调用 DocParser 对文件进行解析和分块
  3. 缓存检查: 检查 workspace/tools 下是否有已处理的缓存
  4. 文档分块: 如无缓存，使用 split_doc_to_chunk 方法按 Token 数量分割文档
  5. 存储缓存: 将分块结果以 JSON 格式存储到本地
  6. 检索查询: 使用搜索算法匹配查询与文档块
  7. 结果排序: 根据相关性评分对检索结果排序
  8. 上下文构造: 拼接 Top-K 个最相关块作为上下文
  9. 回答生成: 将上下文传给 LLM 生成最终回答

性能优化特点

  • 缓存机制: 分块结果持久化存储，避免重复处理相同文档
  • Token 控制: 严格控制上下文长度，平衡信息完整性和计算效率
  • 混合检索: 结合多种搜索算法提高检索准确性
  • 渐进处理: 支持增量式文档处理和检索
