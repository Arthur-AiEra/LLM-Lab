2. LangChain 核心架构

LangChain 是一个用于简化 LLM 应用开发的标准化框架，由以下五大核心组件构成：

  • Models (模型)：对接底层大模型（如 GPT-4, Claude, Qwen），提供统一接口。
  • Prompts (提示)：负责提示词的管理、优化和序列化（PromptTemplate）。
  • Memory (记忆)：解决 LLM 无状态问题，用于保存多轮对话的上下文。
  • Indexes (索引)：RAG 的核心，涵盖文档加载、切分、向量化及存储。
  • Chains (链)：将上述组件串联，如 LLMChain (Prompt + LLM)。

3. Agent 与 ReAct 机制

Agent 的核心在于利用 LLM 的推理能力动态决定工具调用序列。

3.1 ReAct 范式 (Reasoning + Acting)

ReAct 是 Agent 解决复杂问题的标准思维模型，其循环过程如下：

Question: 用户输入的问题
Thought:  分析问题，拆解步骤（CoT 思维链）
Action:   决策调用哪个工具（如 SerpAPI, Calculator）
Action Input: 工具的输入参数
Observation:  获取工具的返回结果
... (循环直至解决)
Final Answer: 最终输出

3.2 LCEL (LangChain Expression Language)

LangChain 的声明式语言，支持流式传输、异步调用和并行执行，用于构建复杂的任务链。

4. 五大 Agent 框架深度对比

针对不同业务场景的选型建议：

框架 核心定位 工作流编排特性 适用场景
LangChain 开发 SDK 线性链 (Chain)，逻辑相对固定。 程序员定制开发，快速原型验证。
LangGraph 图编排框架 循环与状态管理，支持多轮决策/反馈。 复杂多智能体协作、动态逻辑调整。
Coze 无代码平台 可视化拖拽，强依赖插件生态。 非技术人员，快速发布 Bot 到社交平台。
Dify 开源/企业级 自然语言定义工作流，支持 API 集成。 企业内网私有化部署，数据安全敏感场景。
Qwen-Agent 阿里开源 支持三级索引，MCP 协议，长文档处理。 基于 Qwen 模型的深度应用，复杂文档解析。

6. 技术难点 FAQ

Q: LangChain 与 Cursor 的本质区别是什么？ Cursor 是辅助开发的工具（相当于“程序员”），它可以帮你写代码；
LangChain 是应用开发的底层框架（相当于“建筑材料”）。
关系： 你使用 Cursor 编写基于 LangChain 框架的应用程序。
Q: ES (Elasticsearch) 能否替代 FAISS 作为向量库？ 可以。 ES 具备完整的向量检索能力，且支持“混合检索”（关键词+向量），在生产级 RAG 系统中通常比 FAISS 更具优势（支持元数据过滤、分布式存储）。
Q: Tools 与 MCP (Model Context Protocol) 哪个更消耗 Token？ 两者消耗基本一致。 它们本质上都是将工具的 Schema（描述信息）放入 Prompt 中传递给大模型，模型根据描述决定是否调用。
Q: 开发 Coding Agent 推荐使用什么模型？ 推荐使用 Claude Opus 或 Claude Code，它们在代码生成和逻辑推理方面的表现目前优于其他模型。
