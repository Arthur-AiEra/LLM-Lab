↓

↓

思考 (Think) 核心函数：format_next_step_prompt()。
1. 状态获取：读取当前 URL、Title、DOM。
2. [cite_start]元素扁平化：将复杂的 DOM 树转化为 LLM 易读的 [index]<type>text</type> 列表，大幅节省 Vision Token 并提高定位准确率 [cite: 1]。
记忆 (Memory) [cite_start]维护一个 List[Message]。每一步操作的“思考内容”、“工具执行结果”（包含截图 Base64）、“报错信息”都会追加到上下文，形成短期记忆 [cite: 1]。

TOOL 浏览器自动化难点

  • 工具基座: 基于 browser-use 库（对 Playwright 的高级封装）。
  • 核心痛点:
    • 动态组件失效: 如携程的日历弹窗，DOM 结构极深或为 ShadowDOM，导致 clickable_elements 无法提取到日期数字，Agent 陷入“打开-关闭”死循环。
    • 反爬与登录: 很多 OTAs 网站（如去哪儿）有强风控，需要登录才能查看价格。
  • 解决方案:
      [cite_start]
    • GUI-Plus (视觉兜底): 当 DOM 解析失败时，截图发给多模态大模型 (Qwen-VL)，返回物理 (x,y) 坐标进行盲点 [cite: 1]。
    • URL Hack (RAG): 绕过 UI 交互，直接构造带参 URL（如 depdate=2026-01-30）跳转。

ENG 基础设施与安全

  • OpenManus vs Manus:
    • Manus: 闭源，体验好但不可控。
      • [cite_start]
    • OpenManus: MetaGPT 团队开源复刻，架构无堡垒，纯开放，旨在零成本复现能力 [cite: 1]。
  • 安全沙箱 (Daytona):
    • 风险: Agent 可能生成 rm -rf 等恶意代码。
    • 实现: 使用 SandboxManus，在 Daytona 管理的远程 Docker 容器中运行代码。
      • [cite_start]
    • 监控: 通过 VNC 协议将容器内的浏览器画面实时传输给用户 [cite: 1]。

课堂精华 Q&A (实战避坑)

Q: 本地运行 (Local) vs 沙箱运行 (Sandbox) 有什么区别？
• 本地 (python main.py): 直接调用本机的 Chrome 和 Playwright。优点是调试方便，能看到浏览器动作；缺点是有环境污染风险，且需本机安装 Chrome。
• 沙箱 (python sandbox_main.py): 调用 Daytona 远程容器。优点是环境隔离，安全，适合服务器部署；缺点是配置稍繁琐，需 VNC 查看界面。
Q: Agent 经常陷入死循环（如反复点同一个按钮）怎么办？
这是 ReAct 架构的常见缺陷。OpenManus 设置了 max_steps (默认 30) 作为硬限制。工程上建议在 System Prompt 中加入"反思机制"：如果连续两次操作结果相同，强制尝试其他路径或报错。
Q: 如何处理需要登录的网站（如订票系统）？
1. AskHuman 工具: Agent 遇到登录墙时，暂停并弹窗请求用户人工扫码/输入，完成后 Agent 继续接管。
2. Cookie 注入: 预先获取 Cookie 并注入到 BrowserContext 中。
Q: RAG (知识库) 在 OpenManus 中是如何落地的？是向量库吗？
[cite_start]不是向量库，而是 Prompt Context 注入。在 knowledge/ 目录下放置 .txt 文件（如 travel_tools.txt），里面记录特定任务的"捷径"（如 URL 参数模板、特定元素的 XPath）。Agent 启动时会读取这些文件并放入 System Prompt，作为"外挂经验" [cite: 1]。
Q: 为什么有时候提取不到页面信息（如航班列表）？
LLM 视觉 Token 限制或 DOM 结构过深。
优化策略: 修改 System Prompt，告诉 Agent "如果交互元素列表 (Accessibility Tree) 中已包含所需信息，直接整理返回，不要额外调用 extract_content 工具"，节省 Token 并提高速度。
