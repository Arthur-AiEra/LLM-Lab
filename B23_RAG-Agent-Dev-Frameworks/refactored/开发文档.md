2. Milvus Lite vs docker部署
在“企业级高级特性”和“底层索引算法”上确实有阉割，但在你用来做个人知识库的“核心检索体验”上，几乎没有任何阉割，体验是 100% 一致的

    1）核心功能：完全一致（无阉割）

            官方极其聪明地让 Milvus Lite 与完整版共享了同一套底层的 C++ 向量搜索引擎 (Knowhere) 和同一套 Python API (pymilvus)。
            原生混合检索 (Hybrid Search)：Lite 版本完美支持“稠密向量 (语义)” + “稀疏向量 (BM25 关键字)”的双路召回和 RRF 融合打分，完全免费，没有任何类似 ES 的许可证限制。
            增删改查与元数据过滤：所有的标量过滤（比如“只搜索文件名包含 2026 的文档”）在 Lite 中都完美支持。
            无缝迁移：你的代码今天用 Lite 写完（数据存在本地 .db 文件里），明天如果想换成 Docker 版，只需要改一行代码（把连接地址从 xxx.db 改成 http://localhost:19530），其他业务逻辑连一个标点符号都不用动。

    2）被“阉割”的地方（完整版才有的特性）
        为了保持极度的轻量化（可以通过 pip 一键安装），Milvus Lite 舍弃了以下面向大规模生产环境的特性：
        底层索引类型（最核心的区别）：

        Lite 版：目前主要支持 FLAT（暴力穷举算余弦距离）和简单的 IVF_FLAT 倒排索引。
        Docker 版：支持业界最快、最高级的图索引算法 HNSW，以及硬盘级索引 DiskANN，甚至支持 GPU 硬件加速。
        对你的影响：由于个人知识库通常只有几万到十几万个文本块，在你的 M4 芯片上，用 FLAT 暴力穷举连 0.1 秒都用不了，而且 FLAT 提供的是 100% 绝对精准的召回。所以在这个数据量级，你根本感觉不到没有 HNSW 的劣势。
        企业级系统功能：Lite 版不支持复杂的分区（Partitions）、基于角色的权限控制（RBAC，即多用户账号密码）、以及多副本高可用机制。
        数据承载量：Lite 版被硬性设计为处理 100 万 向量级别以下的项目。而 Docker 单机版可以轻松承载上千万甚至上亿级别的向量。


3. 使用 Milvus Lite 替换 Elasticsearch，是个人知识库架构上的一次极其优雅的“减负”。
    你不需要开启任何 Docker 容器，不需要操心端口映射，更不用受限于商业版许可证。所有的向量索引、倒排索引都会被压缩成你项目文件夹里的一个 .db 数据库文件。而且，它原生支持免费的 RRF 混合检索！

    4.setuptools版本冲突
    ```bash
    pip install --user "setuptools<70"
    ```
    setuptoo1s降级到69.5.1（<70)，是为了保留新版本中被删掉的 pkg_resources模块，从而救活底层依赖该模块的pymilvus(Milvus Lite)。
    在这个全局环境中，69.5.1是一个极其经典且稳定的构建版本，绝大多数现代Python包（包括Llamalndex生态下的所有插件)都能在setuptools的60.x~69.x版本上完美运行
