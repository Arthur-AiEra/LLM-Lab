一、四大核心组件深度剖析

1. 大脑 (LLM Adapter)

  • 统一接口: 屏蔽模型差异，提供 invoke(), stream(), batch()。
  • Prompt 解耦: 区分“固定人设”与“动态上下文”，提高 Prompt 复用率。

2. 双手 (Tool Registry)

  • 原理: 将 Python 函数通过内省 (Introspection) 转换为 LLM 可读的 JSON Schema。
  • 调用: LLM 输出 tool_calls → 框架解析 → 执行函数 → 结果反馈 LLM。

3. 记忆 (Context Management)

  • 短期: RunnableWithMessageHistory (LCEL) 实现 Session 级记忆。
  • 长期: VectorStoreIndex (LlamaIndex) 提供 TB 级数据的毫秒级召回。

4. 中枢 (Orchestration)

  • LCEL: prompt | llm | parser 极简管道语法。
  • ReAct: 思考(Thought) → 行动(Action) → 观察(Observation) 的闭环。

二、主流框架选型对比矩阵

框架 核心定位 杀手锏特性
LangChain 全能应用框架 LCEL 语法、极广的生态集成
LlamaIndex RAG 数据专家 Index-First、一站式文档索引
Qwen-Agent 轻量工具型 内置 Code Interpreter、WebUI
AutoGen 多智能体协作 GroupChat、复杂的发言者调度

选型建议：

  • 通用流: 首选 LC，适合需要灵活控制和模型切换的场景。
  • 知识库: 首选 LI，适合 PDF/Word 等海量私有数据问答。
  • 分析流: 首选 QA，适合需要自动写 Python 代码绘图的场景。
  • 流程流: 首选 AG，适合需要多个角色（如分析师+风控）协作。

三、实战要点：RAG 流程与多框架实现

1. 标准 RAG 链路

  • 加载: DirectoryLoader (LC) / SimpleDirectoryReader (LI)。
  • 切片: RecursiveCharacterTextSplitter 保持语义完整。
  • 索引: FAISS (LC) / VectorStoreIndex (LI) 存储向量。
  • 检索: as_retriever() 进行语义相似度召回。

2. AutoGen 的多智能体 RAG

  • DataAgent: 负责调用检索工具获取文档片段。
  • AnalystAgent: 负责对检索到的原始片段进行总结分析。
  • ReviewerAgent: 负责审核回复是否符合事实，避免幻觉。
  • Manager: speaker_selection_method="round_robin" 强制执行 检索→分析→审核 流程。

3. 代码实现速查

  • LC: chain = prompt | llm | StrOutputParser()
  • LI: index.as_query_engine().query("...")
  • QA: bot = Assistant(files=['doc.pdf'], function_list=['code_interpreter'])
  • AG: groupchat = GroupChat(agents=[a1, a2], speaker_selection_method="auto")
