✅ 项目实战：AI质检

需求定义、项目背景、技术栈

  • 背景痛点：传统人工检测存在速度慢、主观标准不一、易受疲劳影响（导致漏检上升）等问题。AI检测具备 24h 稳定运行、10ms级高并发响应（YOLO）的优势。
  • 技术栈：目标检测底座 YOLOv12，多模态零样本分析 Qwen-VL，Web前端工作台 Gradio，数据库 SQLite，数据分析 numpy+matplotlib。
  • 硬件闭环：工业级产线需结合工控机（端侧部署）、高清摄像头、特定打光光源与传送带协作。

EDA数据分析、数据增强

  • EDA分析：探查类别分布（若最大/最小类 > 5:1 需引入 Focal Loss/过采样），并计算缺陷标注框的长宽比以指导 Anchor 配置。
  • 4级增强策略：
    1. 几何变换：旋转(degrees)、翻转(flip)，应对类内形状差异。
    2. 颜色变换：HSV调整、对比度增强，解决光照不均与类间相似问题。
    3. 高级增强(YOLO内置)：Mosaic(4图拼接提振小目标)、MixUp(图层混合)、Copy-Paste、随机擦除。
    4. 离线增强：利用 Albumentations 库进行物理级数据扩充（如 CLAHE 自适应均衡化）。

YOLO 模型训练与调优

  • 数据集配置与基线训练：编写 dataset.yaml 映射图像与6类缺陷标签。环境自适应：CPU 跑 1 epoch 验证流水线，GPU 执行完整 100 epochs 训练。标注需刚好包裹缺陷，单类数据 100-200 张起步，>1000张最佳。
  • 6大渐进式调优策略： 1. 默认基线验证流程 -> 2. 结合缺陷特征配置内置增强(Mosaic/HSV) -> 3. 扩大模型体积(yolo12s)与提升分辨率(imgsz=1280)保留细节 -> 4. 融合离线增强数据 -> 5. 开启推理期 TTA(测试时增强) 免训提分 -> 6. 细致穷举并微调 conf 置信度阈值。
  • 核心评估指标：工业场景将 Recall(召回率) 视为生命线（宁可误报复审，不可漏检放行）。框定位准度依赖 mAP50（IoU>0.5重合过半即算对，工业主力指标）和 mAP50-95（严苛的像素级对齐，多用于竞赛）。

VLM多模态方案

  • VLM零样本缺陷检测：突破 YOLO 依赖重度标注的限制，通过构建系统级 Prompt 强制输出 JSON 格式（含 bbox_2d、英文名、特征描述），即可对全新缺陷进行 Zero-shot 识别，并附带自然语言解释。
  • 坐标系解析痛点：各类大模型底层坐标系不一。代码中需特殊处理：Qwen3-VL 返回的是 0-1000 归一化坐标，需执行 (coord/1000)*尺寸 转换为绝对像素；Qwen2.5-VL 则直接返回绝对像素。
  • 检测引擎统一封装：建立中间层 detection_engine.py，统一输出 DetectionResult 结构。产线应用逻辑为：YOLO 扛并发做实时主力，异常低置信度(边缘Case)样本异步投递给 VLM 耗时复审。

✅ 搭建AI 质检工作台

搭建界面、人工审核、检测记录、统计分析

  • Gradio 5Tab界面：集成 缺陷检测、检测记录(查询)、统计分析(准确率)、数据导出(Bad Case重训包)、竞赛评估(submission生成)。
  • 全数据落库：无论双引擎检测结果如何，全量存入 SQLite。
  • 人工介入审核：质检员对存疑记录执行标记：正确(correct)、误检(wrong) 或 漏检(missed)。系统基于标记状态生成动态统计报表。

持续改进闭环

  • 工业场景核心痛点：受设备老化、光照漂移影响，静止的模型必然衰减，产生大量不可预期的边缘 Case。
  • Bad Case 驱动全流程：自动捞取标记为 wrong/missed 的样本及原图 -> 导出重训包 -> 使用 LabelImg 人工校正标签 -> 合并入原始训练集 -> 启动 GPU 更新模型权重 -> 部署替换。
  • 模型迭代频率指引：
    • 产线初期：数据异构大，每 1-2 周迭代一次（阈值：累积 > 50张 Bad Case）。
    • 稳定运行期：模型收敛，每 1-3 个月迭代一次（阈值：累积 > 200张 或漏检率波动）。
    • 新缺陷突发：一旦出现未见过的底层缺陷，立即触发补充与重训。

搭建你的AI检测助理

  • OpenClaw 架构：基于 Node.js 驱动，配置 openclaw.json 绑定云端 LLM (DashScope) 与 Agent 身份。
  • SKILL 调度机制：为 YOLO 和 VLM 各自创建 SKILL.md。其 description 充当大模型调度的 System Prompt；大模型理解用户意图后，借助 exec 权限组装命令行参数，静默执行底层的 detect.py 推理脚本并吐出 JSON 结果。

💡 底层技术原理剖析

  • 环境隔离与依赖死锁：OpenClaw 具备系统级文件写与 exec 权限，务必沙箱隔离。采用 Node.js(调度层)分离 Python(模型层)能缓解浅层冲突，但在底层 CUDA 算子与深度学习库耦合极深时，依然依赖虚拟环境彻底解耦。
  • 多模态基座对齐逻辑：视觉模型(VLM)能理解图像的本质，在于 Embedding 层预先将图像张量切片并转化为序列化的“图像 Token”，从而突破模态壁垒，直接进入大语言模型的统一向量空间参与自注意力计算。
  • 模型知识蒸馏 (Distillation)：工业级降本提效手段。由高算力云端大模型（如 VLM）处理复杂数据池，清洗并标记出 S1 级别高质量伪标签；随后用这些“标准答案”引导低参数端侧小模型（如 YOLO-Nano）进行轻量化拟合。
  • API Token 调度消耗：即使 Agent 调度框架（OpenClaw）完全私有化本地部署，由于其路由分发、意图拆解依赖大模型思考过程（Chain-of-Thought），每次自然语言交互依然会向底座大模型（如 Qwen-Max）发送上下文，产生 Token 消耗。
  • 后端数据基建演进：SQLite 仅作为本地文件级存储，支撑单机状态留存；工业流水线面临高频并发插入(毫秒级探伤记录)时，必须平滑迁移至强事务机制的 MySQL；若涉及海量批次质量回溯与 OLAP 分析，则需升级至 PostgreSQL。
