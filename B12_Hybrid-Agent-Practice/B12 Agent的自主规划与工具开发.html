2. Agent 核心定义

Agent = LLM + Planning + Memory + Tools

通过 LLM 作为大脑，具备自主理解、规划、执行复杂任务的能力。核心区别于传统自动化脚本的是其自主性 (Autonomy)。

  • 🧠 规划 (Planning)：将复杂目标分解为子任务 (Subgoal decomposition)，进行反思 (Reflection) 和自我修正。
  • 💾 记忆 (Memory)：短期记忆 (Context) 用于上下文学习；长期记忆 (Vector DB) 用于知识检索。
  • 🛠️ 工具使用 (Tool use)：调用外部 API (Calendar, Calculator, Search) 获取信息或执行操作。

4. LangGraph 开发实战

LangGraph 是基于图论（Graph Theory）的 Agent 编排框架，特别适合构建有循环（Cyclic）和状态持久化的复杂应用。

🚀 开发四步曲

  1. 定义状态 (State)：使用 TypedDict 定义工作流中共享的数据结构（如 messages, current_plan）。
  2. 创建图 (StateGraph)：实例化图对象，传入状态类型。
  3. 定义节点 (Nodes) & 边 (Edges)：
    • add_node()：添加处理函数（LLM调用、工具执行）。
    • add_edge() / add_conditional_edges()：定义流转逻辑（确定性跳转 vs 条件跳转）。
    • set_entry_point()：指定起始节点。
  4. 编译与执行 (Compile & Invoke)：workflow.compile() 生成可执行应用，invoke() 传入初始状态。

5. 工程实战要点

  • 时间感知问题：LLM 本身是静态的（预训练数据截止于过去）。若需处理“今年”、“现在”等时间相关任务，必须在 System Prompt 中注入当前时间，或提供 Time Tool。
  • 工具粒度控制：单个 Agent 挂载的工具不宜过多（建议 < 15 个）。若接口过多，应采用多 Agent 架构或按系统接口聚类拆分。
  • Tool Calls 解析：tool_calls 是 LLM 响应中的关键字段，指示 Agent 需要调用的函数名及参数。LangGraph 需解析此字段并执行相应 Node。

6. 工程实战 FAQ

Q: MCP (Model Context Protocol) 与 RAG 有什么区别？ MCP 是一种标准协议，用于连接 AI 模型与数据源/工具。它更像是一个管道标准。
RAG (检索增强生成) 是一种具体的应用模式，用于检索知识库。
关系：你可以构建一个 MCP Server 来提供 RAG 服务，MCP 是接口层，RAG 是功能层。不是知识类的检索（如API调用）更适合直接叫 MCP Tool。
Q: LangGraph 与 Qwen-Agent 怎么选？ LangGraph：适合编排固定、长链路、有状态的工作流（Workflow），你可以精确控制每一步的跳转逻辑。
Qwen-Agent：更侧重于自主规划（Autonomous），适合让 LLM 自己决定使用什么工具，但在长链路控制上不如 LangGraph 精细。
Q: Function Call 和 Agent 是绑定的吗？ 不一定。Function Call 是 LLM 的一项基础能力（输出结构化 JSON 以调用函数）。Agent 是利用这种能力构建的上层系统。你可以仅使用 LLM + Function Call 做简单的任务执行，而不构建完整的 Agent 循环。
Q: 如何处理不需要大模型的情况？ 对于确定性高、逻辑清晰的任务（如固定的数据库查询），直接写代码调用接口即可，无需引入 LLM。LLM 主要用于解决模糊、非结构化、泛化的问题。不要为了用 AI 而用 AI。
