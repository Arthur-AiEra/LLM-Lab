二、 核心模块与函数详细解析

1. 数据准备模块

get_gsm8k_questions(split="train")

功能：加载并预处理 GSM8K 数学应用题数据集。

逻辑梳理：它从 Hugging Face 数据集中心下载 openai/gsm8k。然后通过映射函数，提取每一条数据的 question（问题）和 answer（答案）。最重要的是，它将问题封装进了特定的 SYSTEM_PROMPT 和 XML_COT_FORMAT（即带有 <think> 标签的思维链格式）中，使得模型在输入时就知道需要遵循特定的推理格式。

2. 答案提取与解析辅助模块

extract_xml_answer(text: str) -> str

功能：从模型生成的长篇文本中，精准提取出位于 <answer> 和 </answer> 之间的最终计算结果。

extract_hash_answer(text: str) -> str | None

功能：用于解析原始 GSM8K 数据集中的标准答案。GSM8K 的标准答案通常以 #### 作为最终答案的分隔符，此函数通过字符串分割获取准确的数值答案。

3. GRPO 奖励函数集群 (Reward Functions)

这些函数构成了 GRPO 算法中的“裁判”，负责对模型生成的回答 completions 进行多维度打分。

correctness_reward_func(prompts, completions, answer, **kwargs)

功能：核心奖励函数，判断模型的最终答案是否与标准答案一致。

逻辑梳理：遍历模型生成的多个回答，提取出 <answer> 标签内的文本，并与数据集中传入的真实 answer（经过 extract_hash_answer 处理）进行严格字符串比对。如果一致，给予高分（2.0），否则给 0 分。

int_reward_func(completions, **kwargs)

功能：类型检查奖励。

逻辑梳理：判断模型给出的答案是否是一个纯数字（整数）。这有助于引导模型不要在最终 <answer> 标签里废话，只输出结果。如果是数字给 0.5 分。

strict_format_reward_func & soft_format_reward_func

功能：规范模型的“思考”格式。

逻辑梳理：严格格式打分（Strict）使用正则表达式检查输出是否完全符合 ^<think>...</think><answer>...</answer>$ 的正则结构。宽松格式打分（Soft）只检查字符串中是否包含了这些关键的 XML 标签。符合格式即给予奖励分数，促使模型学会“先思考，后作答”的 DeepSeek-R1 模式。

xmlcount_reward_func(completions, **kwargs) 与 count_xml(text)

功能：防止标签滥用或缺失。

逻辑梳理：统计生成的文本中 <think> 等标签的开闭对数。理想情况下，每个回答只应该有一组思考和答案标签。如果刚好是一对，得 0.125 分；数量不对则倒扣分（0.0 分）。

4. 核心训练配置与执行模块 (主程序流程)

功能：统筹整个大模型的加载、参数配置与强化学习训练过程。

逻辑梳理：

  • 加载阶段：利用 Unsloth 的 FastLanguageModel 加载 Qwen2.5-7B 模型，并设置序列最大长度和 4-bit 量化（针对显存优化）。
  • LoRA 挂载：配置 r=16，目标模块覆盖了所有的注意力矩阵和前馈网络层。
  • GRPO 训练配置：通过 GRPOConfig 配置学习率（1e-5）、批大小等。同时，将上述定义的所有奖励函数以列表形式 reward_funcs=[...] 传递给 GRPOTrainer。
  • 模型保存：训练完成后，支持将 LoRA 权重保存到本地或推送到 Hugging Face Hub，同时支持导出为 16-bit 格式或 GGUF 格式。
