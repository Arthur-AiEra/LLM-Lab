二、 核心模块与功能详细解析

1. 模型与处理器初始化

load_model_and_processor(model_path)

功能：取代 Unsloth 的 FastVisionModel，将 Qwen-VL 原生加载到 Mac 的统一内存中。

底层逻辑：

  • 使用 AutoProcessor.from_pretrained() 加载处理器。VLM 的 Processor 是一个组合体，内部包含了处理图像的 ImageProcessor 和处理文本的 Tokenizer。
  • 使用 Qwen2VLForConditionalGeneration 加载模型本体。为适配 Mac，必须显式指定 device_map="mps" 和 torch_dtype=torch.float16。

2. 多模态 LoRA 配置

setup_peft_lora(model)

功能：使用 Hugging Face 的 PEFT 库配置低秩微调，大幅降低 Mac 显存消耗。

底层逻辑：与纯文本模型不同，视觉模型的线性层更复杂。这里不仅配置了语言模块的注意力机制（如 q_proj, v_proj），可能还会根据需要冻结视觉编码器（Vision Encoder），仅微调语言层和跨模态映射层（Projector），以保证模型原本的视觉特征提取能力不被破坏。

3. 车险多模态数据处理 (最容易报错的一环)

DataCollatorForQwenVL(features) / prepare_dataset()

功能：将“受损车辆照片”与“人工理赔定损单（文本）”组合成模型可读的张量格式。

底层逻辑：

  • 将数据集中的图片路径读取为 PIL.Image 对象。
  • 将对话文本转换为包含 <|image_pad|> 特殊占位符的序列。
  • 交给 Processor，输出 pixel_values（图像被切块后的像素矩阵）和 input_ids（文本标识符）。由于图像分辨率不同，此函数还需负责将不同尺寸的特征补齐（Padding）到相同的 Batch Size 中。

4. 训练执行器

Trainer / SFTTrainer

功能：统筹反向传播和梯度更新。

Mac 特供优化：在 TrainingArguments 中，必须设置极小的 per_device_train_batch_size=1，并开启 gradient_checkpointing=True（用计算时间换取显存空间），否则在处理高分辨率车险图片时，Mac 的统一内存会瞬间 OOM（内存溢出）。
