✅ LLM的模型蒸馏

知识蒸馏的核心思想

  • 采样参数机制： TopP 用于过滤小概率的噪点 Token，保障生成下限 [cite: 874, 878]。Temperature (T) 调节概率分布：推理期用低T（如 0.01）求稳定；蒸馏期用高T（如 3-10）熨平概率分布，暴露小概率事件 [cite: 878, 911, 913, 915]。
  • 本质与标签： 蒸馏是知识的迁移 [cite: 892]。硬标签是唯一绝对答案（信息量少）；软标签输出全词表概率分布，蕴含类别间的相似性判定过程，传递大模型的“暗知识” [cite: 896, 900, 904]。

损失函数与LLM蒸馏

  • Loss 公式： $L_{total}=\alpha L_{hard}+(1-\alpha)L_{soft}$ [cite: 918]。
  • 双师教学： $L_{hard}$（交叉熵）确保基础正确率；$L_{soft}$（KL散度）学习教师的微妙概率分布。$\alpha$ 权重一般设为 0.5-0.7，兼顾标准答案与教师直觉 [cite: 919, 921, 923]。

LLM时代的蒸馏挑战

  • 跨度原则与渐进式蒸馏： 师生参数悬殊（如 671B 教 1.5B）易导致学习障碍（如小学生学研究生课）。需控制比例在 4:1 到 10:1，采用渐进路径：671B -> 72B -> 32B -> 14B -> 7B -> 1.5B 以防梯度断裂 [cite: 876, 928, 931]。
  • 经典蒸馏 vs API 蒸馏： 经典开源蒸馏可获取底层软标签；而闭源 API 蒸馏（如 GPT-5）只能获取最终输出文本（硬标签），丢失暗知识 [cite: 875, 935, 936]。

✅ LLM模型微调与蒸馏实操

unsloth 框架使用

  • 特性： 专为高效微调设计，支持 4bit 量化加载、LoRA 适配器，并集成 vLLM 加速推理。通过 FastLanguageModel 或 FastVisionModel 极大降低显存消耗 [cite: 1086, 1215, 1218]。

CASE：qwen2.5-7B微调 (alpaca-cleaned)

  • SFT (监督微调)： 采用输入输出对进行刚性模仿学习。见效快，但模型能力上限被标准答案锁死，极易变为死记硬背 [cite: 878, 1059, 1370]。

CASE：训练自己的R1模型

  • s1模型与测试时计算： 仅耗资 50 美元通过 1000 个高质量样本进行 SFT 复刻推理能力 [cite: 946, 948]。引入预算强制 (Budget Forcing)：超限时强加结束符终止思考；或追加 "Wait" 字符串引导模型重新检查与自我纠错 [cite: 956, 984, 986]。
  • GRPO强化学习： 摒弃传统 PPO 昂贵的价值网络，通过同组内生成多个候选解计算相对优势进行策略优化（类似 AlphaGo Zero 的自我探索），具备突破天花板的潜能 [cite: 878, 1329, 1338, 1410]。
  • Reward Functions (奖励函数引导 CoT)： 在无思维链数据时，组合 xmlcount、soft_format、int 及 correctness 评分，倒逼模型学会输出 <reasoning> 打草稿 [cite: 1346, 1347, 1348, 1349, 1350]。

CASE：Qwen-VL微调

  • 多模态架构： 纯文本 Tokenizer 无法处理图像，需使用视觉编码器架构。LoRA 配置必须同时开启 finetune_vision_layers 和 finetune_language_layers [cite: 875, 1499, 1500]。
  • 错题本与数据飞轮： 针对特定盲区（如仪表盘 P/R/N/D 挡位识别）收集 Bad Case 重标注微调 [cite: 878, 1589]。利用 AI 自出亿道考题并验证筛出百万级真题，形成反哺下一代的数据飞轮 [cite: 1407, 1409]。

✅ 课堂精华 Q&A

Q1: 为什么小模型无法彻底替代大模型（蒸馏局限）？
A: 模型的参数规模（脑容量）决定了其物理上限和泛化能力。小模型难以像人类大脑（250万亿突触）那样达到融会贯通，模型架构会成为约束的绝对瓶颈 [cite: 875, 878]。
Q2: 经典开源蒸馏与商业 API 蒸馏的核心区别？
A: 经典蒸馏可以获取开源教师模型的软标签（全词表概率分布），获取“暗知识”；API 蒸馏只能拿到商业大模型最终采样的唯一文本（硬标签），学习不够细腻 [cite: 875, 935, 936]。
Q3: GRPO 相比 SFT 的本质优势是什么？能否突破老师上限？
A: SFT 是基于标准答案的刚性模仿，上限被锁死；GRPO 鼓励机器自我探索（无标准推理链），有可能发掘出更优的推理路径，因此具备突破原有能力上限的潜能 [cite: 875, 876, 878]。
Q4: 推理链 (Reasoning) 的效果该如何量化评估？
A: 80% 的核心权重看最终答案（Answer）是否正确；剩余 20% 可作为进阶评估，利用更强的大基座模型（如 Gemini 3 Pro）对其内部推导过程的严谨性和有效性进行 0-100 分打分 [cite: 875, 878]。
Q5: 企业内部私有业务，选 RAG 还是 模型微调？
A: 优先推荐 RAG 处理易变的动态信息。微调通常用于构建基础设施或解决极端垂直领域的认知短板（如特种格式、图像识别），将知识注入模型可免去 RAG 消耗的 Input Token，推理更快，但训练成本高昂 [cite: 875, 878]。
