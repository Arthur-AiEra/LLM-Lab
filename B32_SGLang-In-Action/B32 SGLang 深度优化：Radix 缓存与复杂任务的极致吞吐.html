✅ 企业级AI硬件选型

1. CPU vs. GPU

  • CPU：少量强悍核心，擅长串行逻辑与上下文切换 [cite: 3252]。
  • GPU：海量轻量级核心，专精大规模并发（SIMD），契合深度学习张量需求 [cite: 3252]。

2. LLM的矩阵运算 & 数据搬运 (性能瓶颈)

LLM 推理分为两个核心阶段，产生严重的资源互斥 [cite: 1682, 1683]：

阶段Prefill (预填充)Decode (解码)
机制一次性处理 Prompt 全序列计算 KV Cache [cite: 1668]基于历史缓存，逐字自回归生成 [cite: 1676]
瓶颈计算密集型 (算力墙) [cite: 1669]显存带宽密集型 (内存墙) [cite: 1677]
指标TTFT (首Token延迟) [cite: 1670]TPOT (Token间延迟) [cite: 1678]
策略高算力 GPU + 小 Batch [cite: 1715]大显存 GPU + 大 Batch [cite: 1718]

3. 选型建议与资源配比

  • 选型建议：私企多用 RTX/L/A/H 系列（如 A100 重显存，H100 重算力）；国企多用华为昇腾 [cite: 3252]。
  • PD 分离架构：将 Prefill 和 Decode 隔离到不同 GPU，通过高速互联（如 NVLink）传输 KV Cache，打破资源争抢 [cite: 1744]。

✅ 主流部署框架 (上)

1. 从请求级调度 到 Token级调度

  • 静态调度：短序列干等长序列完成，GPU 严重空转。
  • Token 级连续调度 (Continuous Batching)：细化至 Token 级，生成一词调度一次，空位立即插入新请求，指数级提升吞吐 [cite: 1654, 1766]。

2. CASE：Ollama本地部署大模型

开箱即用，高度适配 GGUF 量化格式，支持 CPU/GPU 混合推理，是 Mac/Win 端侧部署首选。

3. CASE：vLLM高效部署

定位为通用推理引擎（让模型跑得快） [cite: 1656]。核心为 PagedAttention：将 KV Cache 分块存放于非连续显存中，消灭碎片 [cite: 1653]；并支持 推测解码 (Eagle/Medusa) 提升解码速度 [cite: 1772]。

✅ 主流部署框架 (下)：SGLang 推理框架

定位：复杂 LLM 程序运行时，专攻业务逻辑提速（多轮对话、Agent、JSON生成），吞吐及 QPS 可达 vLLM 的 3.5倍 [cite: 1660, 3211]。

1. 核心优化技术

  • RadixAttention (基数树缓存)：利用前缀树自动识别并跨请求复用 Prompt 相同前缀（如 System Prompt）的 KV Cache，消除重复计算 [cite: 2002]。
  • LRU 淘汰策略：显存满时，精准淘汰“最久未使用”的叶子节点，保留公共前缀祖先 [cite: 2003]。
  • 缓存感知调度：打破先到先服务，重排队列，将共享长前缀的请求连续处理，根治缓存抖动，命中率可达 80-95% [cite: 2683, 3163]。
  • 约束解码 (Compressed FSM)：底层运行压缩的有限状态机。将正则表达式转为边压缩状态机，100%保证输出合法 JSON，且能一次解码多 Token [cite: 2710]。
  • API 推测执行：针对商用闭源 API（如 GPT-4），预测生成额外字段缓存，减少 API 调用次数 [cite: 2759]。

2. 部署参数与排错指南

环境强依赖 CUDA 12.4（CUDA 11.8 会报错） [cite: 2936]。

✅ 课堂精华 Q&A

Q: 企业里一般用什么型号显卡部署大模型？跟真实场景差距大吗？
国企/央企偏向华为昇腾芯片；私企常用 RTX, L, A, H 系列。真实场景由于显存和成本限制，通常需要经过多轮性能压测与 PD 架构调优 [cite: 3252]。
Q: 既然 vLLM 吞吐量大，为什么还要用 Ollama？
定位不同。vLLM 专为数据中心高并发设计，不支持 GGUF 极端量化且依赖 Linux/CUDA。Ollama 牺牲并发吞吐，换取了跨平台兼容、低学习成本及端侧低配硬件支持。
Q: 到底什么是 Token 级连续批处理 (Continuous Batching)？
想象一家餐厅（GPU），“请求级调度”是一桌全吃完才安排下一桌。“Token级调度”是“回转寿司”模式，只要有座位空出（遇到停止符），新客人立刻坐下，极大填补空闲算力。
Q: Eagle 和 Medusa 是 vLLM 内部模块吗？跟 PagedAttention 啥关系？
Eagle/Medusa 是推测解码算法，用小模型/外挂头加速大模型预测。PagedAttention 是管理 KV Cache 显存分配的底层基建，贯穿始终。推测解码主要在 Decode 阶段发力 [cite: 1778, 3252]。
Q: 算力指标 FLOPs 和显存带宽在模型不同阶段的影响？
Prefill 阶段是一次性大矩阵乘法，极度吃 FLOPs（浮点运算算力）；Decode 阶段逐字生成，计算量小但需全量读取历史缓存参数，极度吃显存带宽 (GB/s)。
Q: 为什么 LLM 推理越到后面生成越慢？如何通过硬件解决？
因为自回归生成累积的 KV Cache 越来越大。每生成新词需从显存搬运更多历史数据参与计算，触发“内存墙”。需采购高带宽显存（HBM）硬件或用 vLLM/SGLang 优化读写。
Q: Prefill 集群需要生成 Token 吗？
不需要。Prefill 主要对长 Prompt 进行全序列注意力计算提炼 KV Cache。真正的逐字自回归生成是在 Decode 集群完成的 [cite: 1668, 1676, 3252]。
Q: 复用 KV Cache 会导致不同用户会话串台吗？
不会。系统为不同用户独有内容生成独立的分支节点。只复用相同的 Prompt 前缀（如系统设定词），新增内容在 Radix 树中独立隔离 [cite: 3252]。
Q: LRU 淘汰策略具体怎么知道淘汰谁？
通过维护记录节点刷新时间的队列。每次复用节点会更新其时间戳。显存满时，算法扫描并淘汰时间戳最老（最久未访问）的叶子节点腾出空间 [cite: 2003, 3252]。
Q: 约束解码 (Constraint Decoding) 为什么比 Prompt 工程稳定？
Prompt 依赖概率生成，极小概率丢标点导致 JSON 崩溃。SGLang 压缩有限状态机在底层限制仅允许生成符合正则的 Token，实现 100% 格式物理保证 [cite: 3105, 3253]。
