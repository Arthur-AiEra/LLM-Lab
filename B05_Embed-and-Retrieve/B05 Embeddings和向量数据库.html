2. 理论演进：从稀疏 (Sparse) 到稠密 (Dense)

2.1 N-Gram 与特征爆炸

早期的 NLP 使用 One-Hot 或 N-Gram 提取特征，试图通过统计相邻词的共现来捕捉语义。但这种方式会导致矩阵极度稀疏。

💡 课堂重难点：西雅图酒店数据集案例 在课堂上，老师展示了一个 152 * 3347 的矩阵。
  • 152：代表酒店数量。
  • 3347：代表提取出的 N-Gram 特征总数（2元语法）。
痛点： 这是一个典型的稀疏矩阵。因为每家酒店的描述不可能包含所有 3347 个特征，导致矩阵中绝大多数位置都是 0。这不仅浪费存储空间，而且计算相似度（如两个几乎没有重叠词的酒店）变得非常困难。

2.2 Embedding 的革命

Embedding 的核心作用是将高维、离散、稀疏的向量压缩为低维、连续、稠密的向量。它将语义相似的词映射到几何空间中相近的位置。

3. Word2Vec 核心解析

Word2Vec 通过神经网络学习词向量，主要有两种训练模式：

3.1 关键概念

  • 数学直觉： 向量支持代数运算，经典案例：King - Man + Woman ≈ Queen。
  • 参数设置： vector_size (通常 100~300), window (上下文窗口), min_count (最小词频)。

4. 模型选型：MTEB 与 俄罗斯套娃

4.1 MTEB 榜单

MTEB (Massive Text Embedding Benchmark) 是目前最权威的评测榜单。选型时不能只看总分，要根据业务场景（如 Retrieval 检索、Clustering 聚类）查看子榜单。

4.2 🪆 俄罗斯套娃 (Matryoshka Embeddings)

这是 Jina-embeddings-v4 等新模型的核心特性，解决了“维度与精度”的矛盾。

  • 原理： 模型训练出的高维向量（如 2048 维），其前序维度（前 128, 256 维）本身就是高质量的独立向量。
  • 优势：一次训练，弹性部署。
    • 手机端/实时场景： 截取前 128 维，速度快。
    • 服务器/高精场景： 使用 2048 维，精度高。

6. RAG 实战与元数据管理

在 RAG (检索增强生成) 系统中，Embedding 用于筛选与 Query 最相关的 Chunk。

RAG 数据流转时序图
sequenceDiagram participant Py as Python Script participant API as Embedding Model participant FAISS as FAISS Index participant Redis as Metadata Store Note over Py, Redis: 1. 数据入库 (Indexing) Py->>API: 文本 Chunk API-->>Py: 向量 Vector Py->>FAISS: 存入 [Vector, Custom_ID] Note right of FAISS: FAISS只存向量和ID! Py->>Redis: 存入 {ID: "原始文本", Source: "file.pdf"} Note over Py, Redis: 2. 检索 (Retrieval) Py->>API: Query 向量化 Py->>FAISS: index.search(Query_Vec) FAISS-->>Py: 返回 TopK IDs Py->>Redis: 根据 IDs 查回原始文本
🛠️ 工程实战经验：FAISS + 元数据分离 问题： FAISS 专注于向量计算，不存储文本。默认索引是自增整数，难以与业务数据对应。
解决方案： 使用 faiss.IndexIDMap。
  1. 使用 IndexIDMap 包装基础索引，允许传入自定义 ID（如文章 ID）。
  2. 将向量和 ID 存入 FAISS。
  3. 将 ID 和原始文本（Payload）存入 Redis 或 MySQL。
  4. 检索时，FAISS 返回 ID，再回 Redis 查文本。

7. 课堂精华 Q&A 汇总

以下内容整理自课堂实录（TXT文件），涵盖了高频疑问和实战细节。

Q1: 50维、100维这些数字是怎么确定的？里面的数值是什么？ A: 维度大小（Size）是人工设定的超参数。里面的数值（如 0.973...）是模型通过机器学习在大量语料中训练出来的权重。我们无法直观理解每个维度的具体物理含义（它不是简单的“颜色”或“大小”），而是数学空间上的特征表达。
Q2: 什么时候要调整 Embedding Size？ A: 如果语言的理解难度大（如专业领域），Embedding Size 应该大一些（如 1024）；如果追求计算速度或存储受限，则设置小一些。维度越高，精度越高，但计算成本也越大。
Q3: 中英文混合的场景，怎么选 Embedding 模型？ A: 应该选择多语言模型 (Multilingual)，例如 Qwen3-embedding 或 bge-m3。如果是特定的中文业务（如文言文），可能需要单独微调或训练。
Q4: 为什么稀疏矩阵（如152*3347）会有很多0？ A: 因为 3347 代表所有文档中提取出的特征总和（如所有出现的2元词组）。对于某一个具体的酒店描述，它只包含这 3347 个特征中的极少一部分，因此矩阵中绝大多数位置都是 0。
Q5: 本地怎么安装 FAISS？ A: pip install faiss-cpu (如果无GPU) 或 pip install faiss-gpu。
