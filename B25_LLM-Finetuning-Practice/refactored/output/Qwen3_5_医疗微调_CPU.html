2. 各模块功能详细解释

数据处理与加载函数

这一部分定义了从本地环境提取并清洗对话数据的逻辑：

  • read_csv_with_encoding(file_path): 一个高容错的 CSV 读取器。它会依次尝试 gb18030、utf-8、gbk 和 gb2312 编码。如果都失败，会使用 gb18030 结合忽略错误（errors='replace'）的方式强行读取，防止数据加载中断。
  • load_from_jsonl(jsonl_path): 逐行读取 JSONL 格式的文件，并将其解析为 Python 字典列表。
  • load_from_csv(data_dir, max_samples=2000): 从指定的医疗科室子目录（如内科、外科等）中遍历读取 CSV 文件。提取问题和回答字段，过滤掉无效的空值以及长度过短的数据（问题需≥5字符，回答需≥10字符），最多提取 max_samples 条数据。
  • prepare_training_data(): 数据获取的调度中心。它采取优先级策略：优先检查并加载已处理好的 processed_data 目录下的 JSONL 文件，若未找到，才回退调用 load_from_csv 从原始目录处理数据。

主程序流程 (__main__ 内部逻辑)

这是整个微调生命周期的主干，涵盖了从模型加载到导出的 6 个核心步骤：

  • 第一步：加载模型。使用 AutoTokenizer 和 AutoModelForCausalLM 加载指定路径的 Qwen 模型。为了适配 CPU 训练，显式指定了 dtype=torch.float32。同时处理了缺少 pad_token 的情况。
  • 第二步：配置 LoRA。初始化 LoraConfig，设置秩 r=8，缩放因子 lora_alpha=16，并针对自注意力层和前馈层的投影矩阵（q_proj, k_proj, v_proj, o_proj）注入可训练参数。随后通过 get_peft_model 应用该配置。
  • 第三步：准备与格式化数据。调用前述的数据获取函数，将数据转化为 HuggingFace 的 Dataset 对象。定义内部闭包函数 formatting_func，将输入和输出拼接进 MEDICAL_PROMPT 模板，并在末尾追加 eos_token（终止符），随后通过 dataset.map 批量应用。
  • 第四步：SFT 训练。设置 train_kwargs（单设备批次大小1，梯度累积步数2，最大训练步数10等）。实例化 SFTConfig（传入最新的 max_length=512）和 SFTTrainer（传入最新的 processing_class=tokenizer），并执行 trainer.train() 启动训练。
  • 第五步：测试推理。训练完成后，将模型设为 eval() 模式。针对三个内置的测试问题，构造 Prompt，使用 model.generate 生成回答（限制最大生成128 token，温度0.7），并清洗输出只保留回答主体内容进行打印。
  • 第六步：保存 LoRA 模型。在本地创建名为 lora_model_medical 的文件夹，调用 save_pretrained 方法将微调得到的增量权重与分词器持久化保存。
