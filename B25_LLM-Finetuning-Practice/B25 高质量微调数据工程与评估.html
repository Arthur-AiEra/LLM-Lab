一、模型干预边界与范式演进

面对能力不足，应根据知识动态性严格选型：

  • RAG vs SFT：高频动态规则（活动、新闻）必须进 RAG；固定步骤（退换货流程）与常识内化进 SFT，可减少 Prompt Token 提升响应速度。
  • SFT 监督微调：死记硬背 `{"instruction", "input", "output"}`。能力受限于人工标注上限。
  • GRPO 组相对优化：DeepSeek-R1 采用，摒弃外置 Reward Model。让模型生成多组答案自我博弈比较。耗算力极大，但能激发复杂推理，打破人类知识上限（类似 AlphaGo）。

二、高质量数据 Pipeline

垃圾进，垃圾出。 Llama 3 的质变核心就是用 Llama 2 反复清洗出了 15T 极高质量数据。

  1. 清洗去噪：CSV多编码容错（兜底 GB18030），过滤极端长度、空值。使用 MD5 文本哈希去重。
  2. 均衡采样：为避免灾难性遗忘或“偏科”（如内科1万条，男科200条），必须按比例强制均衡抽样。
  3. 格式转换：映射为通用 Alpaca 格式，并在最终文本末尾严格拼接 <eos> 终止符，规范模型生成边界。
  4. BLEU 评估局限：基于 N-gram 匹配，极其死板。同义词（发烧/体温升高）不计分，结构相似但语义相悖（吃感冒药/吃毒药）反得高分。需引入语义级校验。

三、LoRA微调配置与实战洞察

  • CPU/GPU 双路兼容：GPU 用 Unsloth (4-bit 量化, 降显存且快2-5倍) 绑死 CUDA；CPU 退回 transformers+peft 纯 FP32 运算做兜底验证。
  • LoRA 覆盖：不应只挂载 q, k, v, o_proj（注意力机制），还需覆盖 gate, up, down_proj（MLP前馈层，主导非线性推理与知识记忆）。
  • 金融实战合规：大模型并非简单的话术机器。在电销实战中，能根据上下文推理出“爸不在家”及“童声特征”，触发合规红线，主动生成阻断营销的话术，远超传统 NLP 关键词逻辑。

四、纯技术精华 Q&A (踩坑与架构设计)

Q1: SVD矩阵分解与LoRA底层的数学关联是什么？ 核心思想高度一致。SVD 将大矩阵分解为 P×S×Q。工程中无法直接更新几千亿参数的权重矩阵，LoRA 引入低秩自适应，将更新量降维成两个小矩阵 A×B，节省显存且易于与原模型合并。
Q2: AutoDL 上 GPU 微调经常报错，如何解决依赖问题？ 多为环境包依赖冲突。例如较新版本的 transformers 5.3.0 更改了内部 API，导致与当前的 Unsloth 或 PEFT 不兼容。正确操作是使用 AI 助手分析环境变量，将 transformers 降级回 4.51.x 系列，或统一升级 Unsloth 全家桶。
Q3: 100B+ 超大模型显存不足，微调该如何设计？ 单卡不可行。需采用一机多卡（如 8x 4090/A100）或多机多卡分布式并行。结合 QLoRA (4-bit 量化) 极压显存，并设置较大的 Gradient Accumulation (梯度累积) 来等效大 Batch Size，同时相应调低 Learning Rate。
Q4: 企业级多轮对话 RAG 的部门权限应当如何物理隔离？ 绝对不能依赖大模型的软提示（Prompt）。必须在向量数据库引擎层，利用 Tag Metadata（元数据标签），在用户发起检索前进行强过滤（Pre-filtering），确保非授权数据不参与向量计算。
Q5: BLEU 评分有缺陷，频繁调 API 又太贵，有何工程平替？ 推荐 LLM-as-a-Judge 模式。在本地部署一个参数较小但逻辑判断力尚可的开源模型（如 Qwen2.5-7B），封装为本地 API 作为裁判打分。既解决了 BLEU 的语义盲区，又实现了 Token 成本自由。
Q6: 中文垂直领域微调，基座模型应如何选型？ 23年早期习惯用 Llama 等英文基座做全量微调扩展中文词表，但转译中存在严重知识损耗。当前最优解是直接采用中文原生语料极佳的开源模型（如 Qwen3.5/2.5 系列）作为基座，直连 LoRA 增量微调。
Q7: 为什么指令数据 `instruction` 不能精简掉以节约硬盘空间？ 虽然保存为 CSV 时可以只留 Input 和 Output 两列，但在构建 Dataset 进入训练前，必须通过代码动态将固定的 Instruction 和 `` 重新拼接完整。模型需要依靠这些界限符号来学习“何时开始思考”以及“何时停止生成”。
