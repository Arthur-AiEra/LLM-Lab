深度知识解析 (结合 Q&A 笔记)

1. RAG 关键疑难解答

问题点 解决方案与专家建议
混合检索 (Hybrid Search) 笔记重点 指同时使用 BM25 (关键词匹配) 和 向量检索 (语义匹配)。
工具推荐：ElasticSearch (ES) 支持混合检索，而 Faiss 仅支持向量检索。
MRR 指标优化 MRR (Mean Reciprocal Rank) 衡量正确答案的排名。
提升方法： 调整 BM25/Vector 的权重 score，使用 Rerank 模型，优化切片策略 (Small-to-Big)。
Lost in the Middle 原因： Self-attention 机制导致模型对长文本中间部分关注度下降。
对策： 重排序 (Rerank) 将高相关片段放首尾；或者使用 Map-Reduce 分治总结。
精准找数 (如财务表) 不要直接 RAG。推荐 Text2SQL 或让 Agent 写 Python 代码 (Pandas) 来处理 Excel/数据库，保证 100% 准确率。

2. OpenManus 与 浏览器 Agent 实战

Q: 碰到登录窗口怎么办？(OpenManus)
  • 大部分信息采集可以不登录。
  • 如果必须登录，涉及到 Cookies 处理。真实项目中通常使用 Playwright 携带 Cookies 或在无头模式下模拟登录。
Q: 为什么代码阅读困难？(Browser_use)
技巧 1. 先梳理项目结构；2. 定位核心库 (如 browser_use)；3. 让 AI 生成该库的完整工作流示例；4. 增加日志输出 (Logger)。
Q: 死循环如何解决？
检测 Message 相似度 或 Action 历史。如果连续多次执行相似操作且无产出，强制打断并请求人工介入 (Human-in-the-loop)。

3. 必备工具链清单

  • 开发框架： LangChain / LangGraph (通用/状态管理), Qwen-Agent (多文件处理/快速原型)。
  • 监控与日志： 重点 LangFuse (推荐，Manus 适用), LangSmith, Logger。
  • 向量/数据库： ES (混合检索), Milvus/Pinecone/Faiss (向量), MySQL (LangGraph 状态持久化)。
  • 执行环境： Docker / Daytona (沙箱，防止 rm -rf 等恶意代码)。

4. 实战项目高阶标准 (Best Practices)

"优秀的 Agent 系统需要具备可观测性、稳定性和明确的效果评估体系。"
  • SOP 流程化： 任何自动化任务（如生成海报、研报）应先人工跑通流程 (SOP)，再进行 Agent 编排。
  • 项目完整度要素：
    1. 真实的 Use Case (用户旅程图)。
    2. Demo 演示与异常处理机制。
    3. 量化评估： 必须构建测试集（如 50+ 真实问题），监控 Hit Rate / MRR 等指标。
  • 稳定性治理： 具备幻觉检测 (Grounding Check)、死循环熔断机制、Context 长度自适应截断或摘要能力。
