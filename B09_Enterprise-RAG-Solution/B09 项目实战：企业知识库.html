Ingestion解析与分块 (Parsing & Chunking)

核心挑战

PDF转文本需保留表格结构、多栏布局及公式。冠军方案使用了 Docling，备选方案推荐国产 MinerU。

表格处理优化

  • 误区：“表格序列化”（Row-wise Serialization）并未提升效果。
  • 最佳实践：转换为 HTML 格式。LLM 对 HTML 的理解远胜于 Markdown 表格，且能处理合并单元格。

分块策略 (Chunking)

  • 粒度：将每页分割成约 300 tokens (约15句话) 的小块，保持语义连贯性。
  • 元数据 (Metadata)：每个 Chunk 必须记录其所属的 page_id，用于后续的“父页面检索”。
  • 存储：按公司建立独立的 Faiss 索引库（1个公司=1个库），避免数据干扰，通过 Metadata 筛选。

Retrieval多级检索与路由 (Routing & Retrieval)

1. 数据库路由 (DB Routing)

最简单却最有效。从问题中提取“公司名称”，仅在对应的向量库中搜索。将搜索范围缩小 100 倍。

2. 父页面检索 (Parent Page Retrieval)

检索时匹配小 Chunk（指针），但送给 LLM 的是该 Chunk 所属的完整页面。利用上下文信息提升回答准确率。

3. LLM 重排序 (LLM Reranking)

不使用 Cross-Encoder，直接用 LLM (如 Qwen) 对 (Query, Page) 对进行评分。

评分标准：0-1分（0=完全无关, 1=完全匹配）
输出格式：JSON {reasoning: "...", relevance_score: 0.8}
策略：Top 30 Chunks -> Top 10 Pages (经LLM重排)

Generation生成与结构化 (Prompt Engineering)

1. Prompt 路由 (Prompt Routing)

根据问题类型选择特定模板，降低 LLM 认知负荷：

  • Number Prompt: 专注数值提取、单位换算。
  • Boolean Prompt: 专注事实核查 (True/False)。
  • Name/List Prompt: 提取实体或列表。
  • String Prompt: 开放式文本总结 (新增)。

2. 思维链 + 结构化输出 (CoT + SO)

强制 LLM 输出 JSON，分离推理过程与最终答案，减少幻觉。

{
  "step_by_step_analysis": "1. 找到年报第X页... 2. 对比数据...",
  "reasoning_summary": "年报明确指出...",
  "relevant_pages": [12, 15],
  "final_answer": "578亿元"
}

Code代码实现架构 (Architecture)

核心文件结构

  • prompts.py: 集中管理所有 Prompt (System指令, Pydantic Schema, Few-shot示例)。
  • pipeline.py: 串联全流程（解析->序列化->分块->向量化）。
  • text_splitter.py: 实现 Markdown 分块，支持元数据注入。
  • api_requests.py: 处理 LLM 请求，包含 Schema 路由逻辑。

Tech Stack

  • LLM: Qwen-Turbo / Qwen-Plus (支持 128k 上下文)。
  • Parsing: Docling / MinerU (PDF to Markdown/JSON)。
  • UI: Streamlit (快速搭建问答界面)。
  • Protocol: Pydantic (定义输出 Schema)。

Logic复杂逻辑处理

1. 复合查询 (Multi-query)

场景：“苹果和微软谁的营收高？”

策略：拆解 -> 并行查询 -> 综合判断。

  1. 拆解为：“苹果营收是多少？” & “微软营收是多少？”
  2. 分别路由到不同 DB 查询。
  3. 汇总结果给 LLM 生成最终比较答案。

2. 指令细化 (Refinement)

处理“软标准”。例如用户问“CEO是谁”，Prompt 需定义是否包含“总裁”、“董事总经理”等同义职位。需要大量 Corner Case 测试。

💡 课堂精华 Q&A (实战避坑指南)

Q: 为什么不用表格序列化(Serialization)？ 实测发现序列化反而降低效果。LLM 对 HTML 结构的理解能力更强，能处理合并单元格等复杂情况。
Q: Metadata (元数据) 需要向量化吗？ 不需要。Metadata（如年份、页码、公司名）作为过滤器标签使用，仅对 Content 进行 Embedding。
Q: 什么是父页面检索？为什么这么做？ 父级是包含 Chunk 的完整 Page。Chunk 只是索引（指针），回答问题时提供完整页面上下文，能解决跨段落信息丢失问题。
Q: 如何处理成本与精度的平衡？ 如果对精确性要求不高，可以去掉 LLM Reranking步骤，直接使用向量检索的 Top N，以节省 Token 开销。
Q: 100个公司建立100个库还是1个大库？ 推荐100个小库（IndexFlatIP）。结合 DB Routing，查询时只调取对应公司的库，速度快且无干扰。
Q: 结构化输出中的 Schema 是什么？ 是 Pydantic 定义的模板（范式）。强制 LLM 返回 JSON 格式（如 step_by_step_analysis, final_answer），便于程序解析。
