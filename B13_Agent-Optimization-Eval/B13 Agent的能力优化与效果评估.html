01. 混合智能体架构 (Hybrid Agent)

结合“本能反应”与“深度思考”，解决单一模式的局限。

核心分层

  • 反应式层 (Reactive) 毫秒级响应。处理紧急/简单查询（如“上证指数”、“账户余额”）。基于规则或直接API调用。
  • 深思熟虑层 (Deliberative) 深度规划。处理复杂分析（如“投资组合调整”）。涉及多步推理、模型构建、方案生成。
  • 协调层 (Coordinator) 大脑中枢。评估用户Query的复杂度和优先级，动态路由至对应层级。

状态管理 (State)

使用 TypedDict 维护全局状态，包括 query_type (emergency/analytical) 和 processing_mode。

02. 自动化评估体系

从“凭感觉”到“量化指标”，通过 LLM-as-a-Judge 实现自动化测试。

核心指标 (OpenEval)

  • RAG Groundedness (基础性): 评估 LLM 回答是否忠实于检索到的 Context。
    目标：防止幻觉。确保“有理有据”。
  • RAG Retrieval Relevance (检索相关性): 评估检索到的 Context 是否有助于回答 Query。
    目标：检验检索引擎（向量库/关键词）的准确度。

测试流程

Dataset (测试集) → Input (Query) → Output (Agent回答) → Reference (标准答案) → Score

03. 工程化工具链

LangSmith vs LangFuse

  • LangSmith: LangChain 官方出品，擅长 Trace（全链路追踪）和 Dataset 管理。SaaS 体验好但可能有数据合规顾虑。
  • LangFuse: 开源替代品，支持 本地部署 (Docker)，数据更安全。功能涵盖 Trace、Eval、Prompt Management。

Qwen-Agent

自带 GUI 的 Agent 框架，支持 Function Calling。可封装为 TUI (Terminal) 或通过 Flask 暴露为 HTTP 接口集成到业务系统。

04. 能力优化策略

RAG vs Fine-tuning

  • RAG (检索增强): 解决“不知道”的问题。适合需要实时信息、私有知识库的场景。
  • Fine-tuning (微调): 解决“学不会”的问题。当需要特定的说话风格、专业术语或极高的数据质量时使用。

Agent Skills

Agent = System Prompt + Tools + RAG。通过定义清晰的 Function List (如 get_shanghai_index) 扩展能力。

课堂精华 Q&A (实战避坑指南)

Q: OpenEval 中 Groundedness 和 Retrieval Relevance 到底有什么区别？
Groundedness 关注“生成阶段”，检查回答是否由检索内容支撑（防瞎编）； Retrieval Relevance 关注“检索阶段”，检查找回来的资料是否跟问题有关（查得准）。
Q: 生产环境中不想运行 LangSmith/LangFuse 增加开销怎么办？
可以在开发和测试阶段开启监听进行评估，交付上线时关闭或仅在抽样模式下开启。工具主要用于发现瓶颈和Bad Case。
Q: 分类 (Classification) 和 回归 (Regression) 本质区别？
分类是预测离散标签（如用户类型：平衡型/激进型）；回归是预测连续数值（如预测黄金价格、股价）。黄金预测应使用时序模型（如SARIMA）或回归模型。
Q: RAG 运行久了，大模型会自己“学习”到知识库里的数据吗？
不会。除非你拿这些数据去 Fine-tune 模型。RAG 只是临时的“开卷考试”，上下文用完即弃。
