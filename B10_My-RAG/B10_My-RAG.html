2. 核心选型方法论

RAG vs Fine-tuning (微调) 决策矩阵

三种模式（Prompt, RAG, Fine-tuning）并非互斥，常需组合使用。

3. 关键技术栈详解

3.1 分块与索引策略

  • 分块 (Chunking)：直接影响检索粒度。推荐策略：滑动窗口 (Sliding Window)，保留上下文重叠部分，避免语义切断。
  • 分层索引：针对超长文档，采用“父子索引”策略。先检索摘要 (Parent)，再定位到具体详细段落 (Child)。

3.2 检索增强

  • 混合检索 (Hybrid Search)：结合 BM25 (关键词匹配) 与 Vector (语义匹配)。BM25 擅长专有名词精确匹配，Vector 擅长语义理解。
  • 重排序 (Rerank)：在检索回来的 Top-K (如 50 个) 结果基础上，使用高精度的 Cross-Encoder 模型进行精排，筛选出 Top-N (如 5 个) 给 LLM。

4. 性能与生成优化

🚀 延迟 (Latency) 优化
  • 向量检索：使用 ANN (HNSW, IVF) 索引，牺牲微小精度换取速度（毫秒级）。
  • Embedding：使用本地轻量化模型，或异步预计算向量。
  • Cache：对高频 Query 的检索结果进行缓存（Redis）。
⚔️ 知识冲突处理
  • 时间戳：优先使用 metadata 中时间戳最新的文档。
  • 权威度：为文档打标（如“官方文档” vs “社区帖子”），加权排序。
  • LLM 仲裁：检索多来源，Prompt 要求 LLM 显式指出冲突点。

5. 进阶：GraphRAG

当传统 RAG 面对“跨文档推理”或“全局性问题”失效时（如“分析全书人物关系”），需引入 GraphRAG。

  • 核心逻辑：利用 LLM 提取实体 (Entities) 和关系 (Relationships)，构建知识图谱。
  • 检索方式：基于图的遍历与社区发现 (Community Detection)，而非单纯的向量相似度。
  • 适用场景：复杂推理、多跳问答、全集摘要。

6. 工程实战 FAQ

Q: ES (Elasticsearch) 与 FAISS 的关系与区别？ FAISS 是 Meta 开源的向量计算库 (Library)，专注于向量距离的高速计算，本身不具备完整的数据库功能（如持久化、分布式）。
ES 是完整的搜索引擎数据库 (Database)，内置了向量检索能力。如果 Metadata 非常大且需要复杂过滤，推荐使用 ES 替代单纯的 FAISS + 文件存储。
Q: 向量距离 (Distance) 与 相似度 (Similarity) 有何区别？ 两者成反比关系。距离越小，相似度越高。
L2 (欧氏距离)：值越小越相似。
Cosine (余弦相似度)：值越接近 1 越相似。工程中需注意模型输出的度量标准，避免排序逻辑搞反。
Q: 深度学习 vs 机器学习 vs AI 大模型（面试/概念澄清） 机器学习：统计学方法，参数量通常较小。
深度学习：基于神经网络，多层架构 (LSTM/CNN)。
大模型 (LLM)：基于 Transformer 架构，参数量达到亿级 (Billion)，具备“涌现”能力，模拟人类理解。
Q: 本地部署大模型（如 Qwen）的参数量建议？ 在 AutoDL 或本地显卡上，Qwen2.5-32B 是目前性价比极高的选择，在生成质量和资源消耗之间取得了平衡。7B 适合极低资源，72B 需要多卡。
