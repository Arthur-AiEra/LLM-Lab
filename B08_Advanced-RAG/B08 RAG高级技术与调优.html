2. 坚实地基：知识库工程

Small-to-Big (从小到大) 索引策略

原理： 索引时使用“摘要”或“小切片”进行 Embedding，检索时返回其对应的“完整文档”或“大父文档”。

优势： 小切片语义更聚焦，检索命中率高；返回大文档提供了完整的 LLM 上下文，避免断章取义。这在实战中常被称为“父子索引”。

  • 问题生成：利用 LLM 基于文档生成 QA 对，用于扩充检索入口，提升匹配概率。
  • 健康度检查：定期检测知识库中是否存在重复、失效或低质量的切片。

3. 精准雷达：高级召回技术

3.1 查询优化 (Query Optimization)

  • MultiQuery (多重查询)：将用户的复杂问题重写为 3-5 个不同角度的子问题，并行检索，取并集。
  • Query Rewrite (改写)：解决指代不清（如“它多少钱”）或语义缺失的问题。

3.2 混合检索 (Hybrid Search)

结合 BM25 (关键词匹配) 和 Vector (语义匹配) 的优势。

  • BM25：擅长精确匹配专有名词、型号、ID。
  • Vector：擅长捕捉语义、同义词、模糊意图。
  • 融合：通常使用 RRF (Reciprocal Rank Fusion) 算法合并两者的排序结果。

3.3 精细排序 (Rerank)

RAG 系统的“第二道防线”。在 Embedding 粗排检索出 Top-K (如 50) 后，使用 Cross-Encoder 模型进行精细打分，输出 Top-N (如 5)。

4. 全局视野：GraphRAG

解决传统 RAG 无法回答“全局性/概要性”问题（如“数据集的主题是什么？”）的痛点。

模式 Global Search (全局模式) Local Search (局部模式)
适用场景 高层语义 回答概要性问题。
例：“全书讲述了什么故事？”		 具体事实 回答特定实体关系。
例：“曹操和刘备是什么关系？”
核心机制 Map-Reduce：遍历社区摘要，汇总生成答案。 知识图谱遍历：基于实体节点的邻接关系检索。
构建过程 实体抽取 -> 关系提取 -> 社区检测 (Leiden) -> 生成社区摘要。 同左，侧重于索引实体间的边。

5. 工程实战 FAQ (技术避坑)

Q: Rerank 的具体业务流程是怎样的？ 流程： Embedding 检索出 Top-K (例如 30 条)，然后将这 30 条输入 Rerank 模型进行重打分，最终取 Top-N (例如 5 条) 给 LLM。
注意： 虽然 LLM 也能做 Rerank，但成本高（约 0.5元/次），推荐使用专门的 Rerank 小模型（如 BGE-Reranker）。
Q: GraphRAG 这么强，为什么不全部替换传统 RAG？ 成本极高！ GraphRAG 在构建索引（提取实体关系）和 Global Search（Map-Reduce）时会消耗海量 Token。实战建议：简单问题用传统 RAG，复杂推理/全局总结用 GraphRAG，组合使用。
Q: 多模态 RAG (如图片处理) 需要什么模型？ 可以使用 Qwen-VL (Visual Language) 系列。例如 Qwen3-VL-2B-Instruct，本地部署大约需要 6G 显存。
Q: 有哪些好用的开源 RAG 前后端项目？ 推荐：RagFlow (深度文档解析), Dify (工作流编排), FastGPT (易用性), Qwen-Agent (阿里生态)。
Q: 硬件问题：BGE Embedding 模型可以用 CPU 跑吗？ 可以，但速度会慢。Embedding 和 Rerank 模型通常较小，CPU 也能勉强支撑，但在生产高并发环境下强烈建议使用 GPU。
