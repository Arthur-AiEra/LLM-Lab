1. 核心概念辨析

维度 Function Calling MCP (Model Context Protocol)
定位 模型厂商的私有接口（底层能力） 通用的开放协议（类似 USB-C 接口）
开发模式 需为每个模型单独适配（OpenAI/Qwen 格式不同） 一次开发，处处运行（兼容 Claude/Cursor 等）
适用场景 简单、低延迟、单次任务（如查天气） 复杂上下文、跨数据源连接（如连接 Github/数据库）

2.1 Qwen-Agent：注册 Function Calling 工具

核心逻辑：定义工具类 -> 注册 -> Agent 初始化时加载。

from qwen_agent.tools.base import BaseTool, register_tool

@register_tool('exc_sql')
class ExcSQLTool(BaseTool):
    description = '执行SQL查询并返回结果'
    parameters = [{
        'name': 'sql_input',
        'type': 'string',
        'description': '生成的SQL语句',
        'required': True
    }]

    def call(self, params: str, **kwargs) -> str:
        # 1. 解析参数
        sql = json.loads(params)['sql_input']
        # 2. 执行查询 (伪代码)
        df = pd.read_sql(sql, engine)
        # 3. 返回 Markdown 表格
        return df.to_markdown()

3. 课堂精华 Q&A (避坑指南)

Q: Function Calling 和 MCP 可以混用吗？ 可以！ 比如销售场景：先用 Function Calling（内部函数）查询客户日程，再调用 MCP（外部高德地图服务）规划路线。两者互补。
Q: Tools 和 RAG 的调用顺序是怎样的？ 通常是 先 RAG，再 Tools。先通过 RAG 检索历史案例或知识库作为上下文（Few-shot），帮助模型更准确地生成工具调用参数。
Q: 大模型生成的 SQL 会有幻觉吗？如何处理？ 会有。 解决方案：1. System Prompt 中提供详尽的表结构（Schema）；2. 提供 Few-shot 示例；3. 限制查询行数防止慢查询。
Q: 如何调试 MCP 代码？ 使用 MCP Inspector。运行命令 mcp dev your_script.py，它会启动一个本地网页 (localhost:5173) 进行可视化调试。
